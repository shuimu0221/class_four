### 【幻灯片 23】rvec 到底是什么　⏱ 2.5 分钟

> 〔操作〕翻到第 23 页。

好，现在揭晓。刚才那三个数叫 rvec，它的正式名字叫**旋转向量**，英文 rotation vector。一句话，你们记一下：

**它的方向，就是旋转轴的方向；它的模长，也就是这个向量的大小，就是绕这根轴转过的角度，单位是弧度。**

记住，是**弧度**，不是度。弧度跟度的换算大家不陌生，180 度等于 π 弧度。

好，现在回过头，兑现刚才那两个问题。

第一个，为什么只绕一个轴转，只有一个分量在变？现在明白了吧——因为**旋转向量是有方向的**，而这个方向就是你的旋转轴。你绕竖直的那根轴转，这个向量的方向就正好沿着竖直轴，它在另外两个方向上的分量自然就是零，所以只有对应那一个方向的分量在动。你刚才观察到"只有一个数在变"，这不是巧合，**这就是旋转向量的定义本身**。

> 〔停顿〕给学生两秒钟回味。

第二个，为什么转得越多数值越大、还会变号？因为**模长就是角度**。你转的角度越大，这个向量的长度就越长，那个在变的分量也就跟着涨——这正好解释了刚才那个数从 2.01 一路涨上去的现象。至于变号——还是绕这根竖直轴，你往左转 30 度和往右转 30 度，旋转轴的方向正好是反的，整个向量翻了个个儿，那个分量就从正变负了。

所以你看，rvec 这三个数不是随便蹦出来的，每一个数都在描述"往哪个方向转、转了多少"。

那问题来了——为什么 OpenCV 要用三个数来表示旋转，而不是用那个更常见的、3×3 的旋转矩阵？

> 〔停顿〕等一下。

**因为省。** 任意一个三维旋转，其实只有三个自由度，用三个数就够了。3×3 的矩阵有九个数字，但里面是冗余的，它背着一堆约束条件。rvec 三个数，不多不少，刚刚好。

那既然三个数就够，为什么下一页还要出现矩阵、欧拉角、四元数这些别的说法？我们来看。

### 【幻灯片 24】旋转的几种表示法，一张图看懂　⏱ 2.5 分钟

> 〔操作〕翻到第 24 页。

这一页就一张图，但信息量很大。我们把图上的三条箭头一个一个看清楚。

第一条，**旋转向量 rvec，经过 cv::Rodrigues 这个函数，得到旋转矩阵 rmat**。这个转换用的就是**罗德里格斯公式**。注意这条线是**可逆**的——你有一个 rvec，能算出 rmat；反过来，你有一个 rmat，也能用同一个函数算回 rvec。它俩一一对应，转过去、转回来，不丢信息。

> 〔板书〕黑板上写：rvec --（cv::Rodrigues）--> rmat，画成双向箭头。

第二条，**旋转矩阵 rmat，经过反三角函数，得到欧拉角**，也就是我们熟悉的 yaw、pitch、roll 这三个角。这条线的意思是：你手上有一个 3×3 的矩阵，想把它翻译成"先绕哪个轴转多少、再绕哪个轴转多少、最后绕哪个轴转多少"，用反三角函数就能解出来。

第三条，**旋转矩阵 rmat，经过一组转换公式，得到四元数**。四元数就是四个数，w、x、y、z，这个我们下一页还会碰到。

所以你看，**rvec、旋转矩阵、欧拉角、四元数，这四个东西本质上是等价的**——它们说的都是同一件事，就是"这个物体到底是怎么转的"，只是换了一身衣服。什么时候用哪一套，看场景：rvec 省地方，欧拉角给人看最直观，四元数在连续旋转和插值的时候最稳。

那我们这一讲要走哪条路呢？**是 rvec 先变成 rmat，再从 rmat 变出欧拉角这一条。** 为什么？因为等一下 P5 里的 Task 05，要的就是这个——它让你用 `cv::Rodrigues` 把 rvec 转成旋转矩阵，再用反三角函数把 yaw、pitch、roll 解出来。所以下一页，我们就把最后这一步**讲透**。

### 【幻灯片 25】从旋转矩阵提取欧拉角（INT_YXZ 约定）　⏱ 3.5 分钟

> 〔操作〕翻到第 25 页，标题是"从旋转矩阵提取欧拉角（INT_YXZ 约定）"。这一页是本讲最重要的理论页，速度放慢。

先看标题里那个缩写，**INT_YXZ**。这是这一页所有公式的前提，叫**旋转顺序**，也叫**约定**。

为什么非得先约定？因为欧拉角不是一步转到位，它是**分三步转**的：先绕一根轴转一个角，再绕第二根轴转一个角，最后绕第三根轴转一个角。Y、X、Z 就是这三根轴的先后顺序——先绕 Y、再绕 X、最后绕 Z。**顺序一换，同一个姿态算出来的三个数就完全不一样。** 所以公式表头才要标 INT_YXZ。记住：**用公式之前，先认约定。**

好，约定认完了，我们看公式。先说一个记号：我们把旋转矩阵 rmat 的第 i 行、第 j 列这个元素，记作 **m 下标 i j**。整张表就三个式子：

```cpp
// rmat 的第 i 行第 j 列元素记作 m_ij
yaw   = atan2( m13, m33 )
pitch = -asin( m23 )
roll  = atan2( m21, m22 )

// 注意：atan2 / asin 算出来是弧度，乘 57.3 (≈180/π) 换算成角度
```

我们一个一个看。

第一个，为什么用 **atan2**？atan2 叫**两参数的反正切**，是 C++ 标准库里就有的函数——`std::atan2(double, double)`，吃两个参数：分子的 y、分母的 x。它比旁边 asin 的值域宽得多——atan2 能给出负 180 度到正 180 度，一整圈都能表示；asin 只能给出负 90 到正 90 度，半圈。原课专门强调过，atan2 是两参数的反正切，这个一定要记住。

第二个，pitch 用的是 **asin**，反正弦。那它前面为什么带个负号？这也是**约定**带来的——因为我们这套公式是按 YXZ 的顺序推出来的，推到最后符号就落成了这个样子。你换一套约定，这个负号可能就没了。所以你不用去背这个负号的来路，你只要知道：**它是约定的一部分，跟着约定走。**

第三个，roll，也是 atan2，取的是 m21 和 m22。

> 〔停顿〕让学生把三个式子抄下来。

好，公式抄完了。接下来这一条，是我今天最想让你们记住的一步，也是**往届学生最容易错的地方**。

你们注意看公式里这些下标：m13、m33、m23、m21、m22。这些下标**都是从 1 开始数的**——m13，就是第 1 行、第 3 列。

但是，我们代码里的 rmat 是一个 **cv::Mat**。cv::Mat 的下标，是**从 0 开始**的。后面 Task 05 的代码注释里专门写了这一句：**cv::Mat 的下标从 0 开始，而不是 1。**

> 〔板书〕左边一列写公式下标，右边一列写代码下标，中间画对应线。

所以，公式里的 m13，在代码里要写成 `rmat.at<double>(0, 2)`——你看，第 1 行变成 0、第 3 列变成 2，**每个下标都减了一**。同理，我们把这五个都对应上：

> 〔板书〕
> m13 → rmat.at<double>(0, 2)
> m23 → rmat.at<double>(1, 2)
> m21 → rmat.at<double>(1, 0)
> m33 → rmat.at<double>(2, 2)
> m22 → rmat.at<double>(1, 1)

**就差这一个 1，数错一个，全盘皆错。** 你们等一下在 P5 写 Task 05 的时候，如果算出来的角度莫名其妙、跟实际转的方向对不上，第一件事就回来查这五个下标，看是不是忘了减一。这是我们今天反复要强调的一个点。

最后看一下幻灯片最后那行注释。它写着：atan2、asin 算出来是**弧度**，乘 57.3——也就是 180 除以 π——换算成角度。

这里我要提醒一句口径：**我们工程里的代码，是把弧度直接显示出来的，没有乘 57.3。** 所以等一下你在画面上看到的 yaw、pitch、roll，都是很小的数，零点几这种，那就是弧度。幻灯片上这句"乘 57.3"，是给你们的方法——**你想看度数，就自己乘 57.3。** 千万别把这两个口径搞混了，别以为屏幕上打出来的是度数。

### 【幻灯片 26】欧拉角的坑：万向锁　⏱ 2 分钟

> 〔操作〕翻到第 26 页。左右两栏，一栏欧拉角，一栏四元数，对比着看。

好，P4 最后一页，讲欧拉角的坑。

左边这一栏，欧拉角的好处是**直观、好理解**——"飞机抬头 30 度"，谁都听得懂。但它有两个短板。第一，**表示不唯一**——换个旋转顺序，同一个姿态算出来的三个角就完全不同，所以别人给你一组欧拉角，你不问约定就没法用。第二，就是这页标题——**万向锁，Gimbal Lock**。名字听着吓人，道理很直观：欧拉角就像**三个环套在一起**，正常时各管一个方向的转动。可当你转到某个特定角度，比如中间那个环转到了 90 度，**两个环就重合到一起了**——本来它俩管两个方向，现在只管一个方向了。**三个自由度，一下子丢了一个。**

> 〔停顿〕留两秒。

丢一个自由度意味着什么？意味着在这个姿态附近，你往那个丢了的方向怎么转，角度都表示不出来，运动就"卡住"了。这就是万向锁，点到为止，今天不推导。

右边这一栏的四元数，就是来解这个问题的：四个数 w、x、y、z，**没有奇异点**，连续旋转、插值特别稳；缺点是不直观。今天也不展开。

不过这个挺好玩的，我现场带你们玩一下。

> 〔演示〕打开浏览器，访问 quaternions.online，投到屏幕上。

看屏幕。左边一列是 Quaternion，四个输入框 W、X、Y、Z；右边一列是 Euler Angles，三个输入框 X、Y、Z，旁边一个下拉框叫 XYZ-Order，就是刚说的**旋转顺序**；中间是三维网格，红 x、绿 y、蓝 z。我先动右边欧拉角，把 X 调大——网格跟着转了；再调 Y、再调 Z，都实时跟着动。现在我把左边四元数的 W、X、Y、Z 也调一遍，让姿态跟刚才**一模一样**——看到没有？**两组完全不同的数，描述同一个姿态。** 这就是"本质等价"。
