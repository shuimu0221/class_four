### 【幻灯片 28】Task 04 · 把 tvec / rvec 打印到画面上　⏱ 5 分钟

> 〔操作〕翻到第 28 页，把代码块放大。

看第 28 页，Task 04。大家把代码往下拉，找到标着 Task 04 的那两行 draw_text。你现在看到的是这个：

```cpp
tools::draw_text(img, fmt::format("tvec:  x{: .2f} y{: .2f} z{: .2f}", 0.0, 0.0, 0.0), cv::Point2f(10, 60), 1.7, cv::Scalar(0, 255, 255), 3);
tools::draw_text(img, fmt::format("rvec:  x{: .2f} y{: .2f} z{: .2f}", 0.0, 0.0, 0.0), cv::Point2f(10, 120), 1.7, cv::Scalar(0, 255, 255), 3);
```

你的任务就一句话：**改写这两个 draw_text 的参数，把真正解出来的 tvec 和 rvec 打到画面上。** 现在它俩打印的全是 0.0——那是我写死的占位符，不是真值。上一段 Task 03 你辛辛苦苦解出来的数据，就在 rvec、tvec 这两个变量里躺着，得把它请出来。

那怎么把一个数从 tvec 里取出来？关键就在幻灯片上这句提示：`tvec.at<double>(0)`。我拆开讲。

tvec 是 solvePnP 吐出来的一个 3×1 的 cv::Mat。注意，**它是 cv::Mat，不是数组，也不是 vector。** cv::Mat 是 OpenCV 里存矩阵的容器，你要从里面取一个元素，不能像数组那样中括号一括，得用 `.at<类型>(下标)` 这个函数。

- 尖括号里的 `<double>`，是告诉它：我要取的这个元素是个 double。tvec 内部存的就是 double。
- 后面圆括号里的 0，是下标，表示取第几个元素。
- 所以 `tvec.at<double>(0)` 得到的是一个 double，就是 tvec 的第一个元素。

三个下标 0、1、2，正好对应 x、y、z 三个方向——0 是 x，1 是 y，2 是 z。rvec 一模一样的写法：`rvec.at<double>(0)`、`(1)`、`(2)`，同样是 x、y、z。

所以你要做的，就是把原来的三个 0.0，换成 `tvec.at<double>(0)`、`tvec.at<double>(1)`、`tvec.at<double>(2)`；下面那行 rvec 照做一遍。格式串不用动，`{: .2f}` 原样保留，参数的个数也还是三个。

这里我必须钉死一件事，别想偏了：**Task 04 就是把数字打印到画面上，就这一件事，没有别的。** 这一页的核心，是让你亲手体会一次——**怎么从 cv::Mat 里，把一个元素抠出来。** 这个动作，下一段 Task 05 你还要再用一次，而且一抠就是好几个。

### 【幻灯片 29】Task 05 · rvec → rmat → 欧拉角　⏱ 6 分钟

> 〔操作〕翻到第 29 页，把代码块放大。

好，第 29 页，Task 05。这是本讲最后一个 Task，也是最综合的一个。它把我们 P4 讲的整条链路——rvec 到 rmat 到欧拉角——真正落到代码上。分三步走。

第一步，**声明旋转矩阵，调用 Rodrigues。**

```cpp
cv::Mat rmat;
cv::Rodrigues(rvec, rmat);
```

`cv::Mat rmat;` 是开一个矩阵变量，用来装我们的旋转矩阵。然后 `cv::Rodrigues(rvec, rmat);`——把旋转向量 rvec 转成旋转矩阵 rmat。P4 那张流程图上第一条箭头，就是这一行代码。记住，这个函数是帮你把 rmat 原地填好的，你不用管它内部怎么算。

第二步，**套 INT_YXZ 公式，算三个角。** 公式上一段刚在 PPT 第 25 页讲过，我念一遍，你对着看：

```
yaw   = atan2( m13, m33 )
pitch = -asin( m23 )
roll  = atan2( m21, m22 )
```

关键在这儿——**公式里的 m13、m23 这些，都是"第几行、第几列"，是从 1 开始数的；可 cv::Mat 的下标是从 0 开始数的。** 所以每一个下标都要减一。这个对应关系，上一段我带着你们推过，这一页的提示里也写了 `rmat.at<double>(0, 2)`。现在我不直接给你答案，你自己对着写：m13 是第 1 行第 3 列，到代码里是几？m23 呢？m21、m33、m22 呢？

> 〔停顿〕二十秒左右，等学生把五个对应关系动笔写完。

m13 是第 1 行第 3 列，代码里就是提示里给的那个例子 `rmat.at<double>(0, 2)`——行、列都减了一。剩下的 m33、m23、m21、m22，你自己按同一个规矩写，写完对着提示里的例子检查，先别问、也别看旁边同学的。

写的时候盯住这个格式：`rmat.at<double>(行, 列)`，两个下标，中间一个逗号——这就是 cv::Mat 取二维元素的方式。它比刚才 tvec 多一个下标，因为矩阵是二维的，得分行、列。五个下标你全对上了，公式这一关就算过了。

第三步，**把这三个变量，喂给第三行 draw_text。** 还是老动作——把 yaw、pitch、roll 这三个变量，填进第三行 draw_text 的参数里，格式串不用动。

画面上第三行，就是这三个角。

好，这里有一个口径我要钉死，特别容易讲混：**画面上显示的这三个角，是弧度，不是度数。** 因为 atan2、asin 算出来天然就是弧度。所以你会看到 yaw 大概是 0.1 这种很小的数——**小，不代表错，它就是弧度。** 想看度数怎么办？上一段 P4 第 25 页的幻灯片上写过——乘 57.3，也就是乘 180 除以 π，就换成度了。这个换算你心里有数就行，代码这一版不带乘，我们先看弧度。

那我考考你们——

「yaw 现在大概是 0.1，有谁知道，这是多少度？」

> 〔停顿〕等学生心算。

> 〔应答〕
> · 学生答"乘 57.3，大概 5.7 度" → "漂亮！0.1 乘 57.3 差不多就是 5.7 度。你看，弧度这个数看着小，换过来其实就是个很正常的偏角。"
> · 学生答"5 度左右" → "方向对了。精确说 5.7 度左右，因为 1 弧度大约 57.3 度。"
> · 学生答"不懂怎么算" → "就是乘 57.3。0.1 乘 57.3，五点几度，你按一下计算器就知道了。"
> · 冷场 → 老师自己接："我算一下——0.1 乘 57.3，大概 5.7 度。这个 57.3 就是 180 除以 π，记一下。"

常见错误几个，我提前标出来：**行列搞反**——把 `(0, 2)` 写成 `(2, 0)`，这俩元素数值不一样，出来全是错的；**忘了公式下标要减一**，直接写 (1, 3)，可 cv::Mat 第三列是 2 不是 3；**pitch 前面的负号丢了**，`pitch = -asin(m23)`，那个负号不能少；还有就是**以为显示的是度数**，不是，是弧度。

好，动手。

### 巡场话术库（Task 04~05 通用，老师走下讲台时用）

> 〔操作〕在学生中间走动，遇到下面几类情况，照这个思路说。

**情况一：画面上数值一直是 0.00。**
「你这是 Task 04 还没动过吧？看那两行 draw_text，后面是不是还挂着 0.0、0.0、0.0？把三个 0.0 换成 `tvec.at<double>(0)`、`(1)`、`(2)`，rvec 那行照做。改完保存、重新编译。」

**情况二：编译报错，卡在 at 这个模板上。**
「报错里出现 at 了是吧？多半是尖括号或者圆括号写漏了。正确写法是 `tvec.at<double>(0)`——`.at` 后面尖括号里写 double，圆括号里写下标。别写成中括号 `at[double]`，也别漏了那对尖括号。还有，取二维元素要两个下标，比如 `rmat.at<double>(0, 2)`，中间的逗号别丢。」

**情况三：欧拉角数值不对，或者行列搞反了。**
「算出来某个角一直是 0，或者是 nan，或者跟板子的转动方向对不上？先查下标顺序。公式里是 m13，第 1 行第 3 列，代码里就是 `(0, 2)`——别写成 `(2, 0)`，那两个数不一样。再检查一下，是不是每个下标都忘了减一。这俩是重灾区。」

**情况四：以为角度单位是度数。**
「你盯着那个 0.1 发愁，觉得太小了？它**是弧度，不是度**。弧度就长这样，0.1 大概是五点几度。想看度数，乘 57.3。代码这一版不乘，我们就看弧度。」
