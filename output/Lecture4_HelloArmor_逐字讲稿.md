### 【幻灯片 8】位姿 = 位置 + 朝向　⏱ 2 分钟

> 〔操作〕翻到第 8 页，鼠标点到"位姿"这个词上。

我们先看第一个概念。刚才一直说"位姿、位姿"，其实它是两个字拼起来的：一个是"位"，一个是"姿"。"位"就是位置，"姿"就是姿态，也就是朝向。

位置好理解——它就是装甲板中心，在相机坐标系下的一个三维坐标，写成 x、y、z 三个数。这三个数说白了，就是告诉相机：这个目标在你右边多少、下面多少、前面多远。

难的是第二个，朝向。装甲板"转了多少度、往哪边转"，这个怎么用数字说清楚？

> 〔停顿〕等两三秒，看有没有人回答。

> 〔应答〕
> · 学生答"看它朝哪边歪" → "对，方向是这么回事。可'歪'这个字程序听不懂，我们得把它变成数。"
> · 学生答"转了多少度" → "很接近了。可往哪边转、绕哪根轴转，也得一并说清楚。"
> · 学生答"朝向不就是它在哪吗" → "不对，这是两码事——位置管'它在哪'，朝向管'它脸朝哪边'，两个都得有，缺一个都算不出完整位姿。"
> · 冷场 → "我先卖个关子——它后面会用一个向量来表示，现在先把它的样子想明白就行。"

我借一个大家都熟的东西来讲——飞机。飞机在天上，除了往前飞，还有三个转动的方式，我们一个一个看。

> 〔演示〕双手张开当机翼，平举在胸前。

第一个，偏航，英文 yaw。它绕哪根轴？绕"上下"这根轴——你想象从飞机头顶往下穿一根竖着的杆子。绕这根轴转，改变的是前进的方向，也就是朝向的左右。

> 〔演示〕身体不动，双臂水平地整体向左、向右转。

第二个，俯仰，英文 pitch。它绕"左右"这根轴，也就是两个机翼连成的那根杆子。绕这根轴转，改变的是抬头、低头的程度。

> 〔演示〕双臂保持成一条水平直线，随上半身一起向前下方俯、再向后上方抬，模拟机头低下和抬起。

第三个，横滚，英文 roll。它绕"前后"这根轴，从机头指向机尾。绕这根轴转，改变的是侧向倾斜的程度——飞机往哪边歪。

> 〔演示〕双臂一上一下地翻转，像飞机往一边压坡度侧倾。

这三个词，yaw、pitch、roll，后面天天要用。

> 〔操作〕站直身体，用手比出三根轴的方向，放慢语速。

**这里有一个特别关键、很多同学第一次都会漏掉的点：这三个转动不是随便转的，它们是按特定顺序定义的。** 顺序是——**先绕上下轴偏航，改变前进方向；再绕左右轴俯仰，改变俯仰程度；最后绕前后轴横滚，改变倾斜程度。** 而且更重要的后半句是：**每一步都是在前面那一步转完之后的结果上再继续转**，不是三个轴各转各的、最后再加起来。顺序不能乱——你把顺序一换，同样这三个角度，转出来的姿态就不一样了。

> 〔板书〕顺序：先 yaw（绕上下轴）→ 再 pitch（绕左右轴）→ 后 roll（绕前后轴）；每一步在前一步的结果上转。

现在不用记公式，先把这个画面记住：**偏航管左右，俯仰管抬头低头，横滚管歪；而且三步有先后，一步踩一步。**

好，收一下——看出一块装甲板的三维信息，无非两样：**距离远近**和**朝向左右**。距离用位置这个三维向量描述，朝向就用刚才这三个角描述。可问题来了——**程序能自己解算吗？** 想解算，得先给它一个参照的坐标系。翻页。

### 【幻灯片 9】先认清两个坐标系　⏱ 2 分钟

> 〔操作〕翻到第 9 页。这一页今天特别重要，讲慢一点。

> 〔操作〕鼠标圈一下上半部分。

先看第一个，叫**装甲板局部坐标系**。注意，它是长在装甲板自己身上的，跟着装甲板一起动。原点在哪？就在装甲板的中心。三个轴怎么定？x 轴向右，y 轴向下，z 轴指向板子外面，也就是朝向镜头这一侧。你可以在脑子里把这块板子立起来：x 往右伸、y 往下伸、z 朝你这边戳过来。

> 〔操作〕鼠标移到两个数字上，放慢语速，这里让学生动笔。

然后是今天一定要用到的两个物理尺寸，大家拿笔记一下：灯条之间的宽度，ARMOR_WIDTH，等于 **0.135 米**；单根灯条的长度，LIGHTBAR_LENGTH，等于 **0.056 米**。**划重点——这两个数等下写代码的时候立刻就要用，就是上机实验里的 Task 01 要拿去搭那四个 3D 点。所以别听完就忘，先记下来。** 它俩一横一竖，别搞反：0.135 是两根灯条之间的横向宽度，0.056 是单根灯条竖着的长度。

再看第二个坐标系，叫**相机坐标系**。它的原点在哪？在镜头的**光心**，也就是镜头正中间那个点。相机坐标系跟相机是绑死的：相机往哪平移，它就跟着平移；相机往哪转，它就跟着转。相机看到的一切，最后都要换算到这个坐标系里来描述。

> 〔停顿〕等学生把两个坐标系的定义和两个数字抄下来。

那我们把这两个坐标系摆在一起，目标是什么？一句话：算出"装甲板坐标系"相对于"相机坐标系"的**旋转 R** 和**平移 t**。这个 R 描述朝向，这个 t 描述位置，R 和 t 合起来，就是我们今天要的位姿。

好，两个坐标系立好了，目标也清楚了。那再追问一句——我们为什么非要姿态不可，光知道位置不行吗？翻页。

### 【幻灯片 10】工程上为什么必须要"姿态"，不只是"位置"　⏱ 1.5 分钟

不行。这里有两个工程上的理由。

> 〔操作〕鼠标指第一条。

第一，相机和枪管往往不重合、也不共轴。你想，相机装在车顶，枪管在下面，这俩根本不是同一个点。那如果你只用画面正中心去瞄准，就会有一个系统性偏差——你永远偏那么一点点，而且这个偏差是固定的，不会自己消失。

所以记住这句话——**2D 检测解决"看见"，3D 位姿解决"打中"。**

### 【幻灯片 12】Perspective-n-Points 问题　⏱ 3.5 分钟

> 〔操作〕翻到第 12 页。
> 〔板书〕黑板中间画一道竖线，左边写"已知"，右边写"求"。

这一页的名字叫 Perspective-n-Points，翻译过来就是"透视 n 点问题"，简称 PnP。名字听着唬人，我们把它拆成两半就懂了：Perspective 是"透视"，说的是相机成像的那个透视投影；n Points 是"n 个点"，说的是我们手里有 n 组对应的点。

那我们就用刚才立的那个框架来拆——先看"已知什么"，再看"求什么"。

> 〔板书〕在"已知"那一侧写：n 组一一对应的点。

已知的第一样东西，是**一一对应的 n 组点**。什么叫一一对应？我们手里其实有两串点。

一串在**装甲板自己的局部坐标系**里，就是前面 P1 讲的那个"x 向右、y 向下、z 指向板外"的坐标系。它上面有 n 个三维点，这些点的坐标是我们自己定下来的，因为板子的真实尺寸我们知道——多大、点在哪，我们说了算。

另一串在**图像上**，是检测器已经给出来的 n 个二维像素点，也就是照片上那块装甲板、两根灯条的端点。

关键就在"对应"这两个字上：装甲板上第 1 个点，必须对应图像上第 1 个点；第 2 个对应第 2 个……一个萝卜一个坑，不能错位。这一点我们讲到接口的时候还会再强调一遍，因为它是新手最容易翻车的地方。

> 〔停顿〕两秒。

已知的第二样东西，是**相机的内参和畸变系数**。

内参是什么？你把它理解成"这个镜头把三维世界投影到照片上的方式"，主要就是**焦距**和**主点**。焦距管"东西在照片上被放大多少"，主点管"照片的中心落在哪个像素上"。换一个镜头、或者换一个分辨率去拍，同一块装甲板落在照片上的位置就不一样了，所以内参必须跟着"当前这个镜头、当前这个分辨率"走。

畸变系数呢，是因为真实镜头不是理想的小孔，画面边缘会有弯曲，畸变系数就是用来把这个弯曲修正回来的。

> 〔板书〕在"已知"那一侧补一行：相机内参（焦距、主点）+ 畸变系数。

好，已知说完了，我们看"求什么"。

> 〔板书〕在"求"那一侧写：旋转 R 和 平移 t。

我们要求的，就是两样东西：一个**旋转 R**，一个**平移 t**。R 管的是**朝向**——这块板子是怎么转的、往哪边偏；t 管的是**位置**——这块板子相对相机，摆在前方多远、偏左偏右、偏上偏下。**R 加 t，合起来就是我们要的那个位姿。**

那凭什么 n 个点就能把 R 和 t 反推出来呢？我打个比方，你马上就有感觉了。

假设你眼前有一个球，你知道这个球真实的直径有多大；然后你在照片上量一下它看起来有多大——你是不是立刻就能估计出它离你多远？它看起来越小，说明它离得越远。再比如，你知道一块砖的真实长度，又在照片上看见它斜着摆——那你多多少少能判断出它是朝哪边斜的。

这就是透视的基本直觉：**真实尺寸，加上它在照片上的样子，就能反推出"离多远"和"摆成什么角度"。** 我们做的是一模一样的事情，只不过我们用的是四个点，要求也更严格一点——不光要"离多远"，还要"转了多少"。

好，这就是 PnP 问题。我把它拧成一句最短的话，你记一下：**已知 n 组一一对应的点，再加上相机内参和畸变系数，求物体相对相机的旋转 R 和平移 t。** 记住这个"已知什么、求什么"，下一页我们就看 OpenCV 怎么把它打包成一个函数。

### 【幻灯片 13】cv::solvePnP 函数签名精讲　⏱ 5.5 分钟

> 〔操作〕翻到第 13 页，屏幕上出现 solvePnP 的签名。

好消息是——我们刚才讲的那一整套，OpenCV 已经全部封装好了，就一个函数：`cv::solvePnP`。

它的用法非常朴素：**你只管把数据"喂"进去，它把结果"吐"出来。** 所以这一步我们不需要会数学，我们需要搞清楚的是——每个参数是什么、谁提供、长什么样。这一页我们一个参数一个参数过，慢一点，因为它就是你 Task 03 要写的东西。

> 〔操作〕用鼠标从头到尾划过六个必填参数，划一个讲一个。

```cpp
bool cv::solvePnP(
    InputArray  objectPoints,   // 输入：物体局部坐标系下的 n 个点
    InputArray  imagePoints,    // 输入：图像上对应的 n 个点
    InputArray  cameraMatrix,   // 输入：相机内参矩阵（我们会提供）
    InputArray  distCoeffs,     // 输入：畸变系数（我们会提供）
    OutputArray rvec,           // 输出：旋转向量
    OutputArray tvec,           // 输出：平移向量
    bool useExtrinsicGuess = false,
    int  flags = SOLVEPNP_ITERATIVE
);
```

先看前两个。这是六个里最重要的两个，也是必须严格对应的两个。

第一个，`objectPoints`——**物体局部坐标系下的 n 个点**。谁提供？**你自己提供**，它就是 Task 01 里你要填的那个 `object_points`。它长什么样？它是一个点集，每个元素是 x、y、z 三个数。对装甲板来说，n 就是 4，也就是我们在装甲板坐标系里定义的四个点。

第二个，`imagePoints`——**图像上对应的 n 个点**。谁提供？**检测器提供，你来搬运**，它就是 Task 02 里你要填的那个 `img_points`，是从装甲板的端点里取出来的四个二维像素点。它每个元素是 x、y 两个数。

注意了——`objectPoints` 里的第 1 个点，和 `imagePoints` 里的第 1 个点，描述的必须是**同一个物理位置**。你 3D 点那边第一个填的是左上，2D 点这边第一个也必须是左上，顺序一点儿都不能岔。**这是整个 Task 03 里最容易出错的地方，没有之一。** 这一页你要是只让我记一句话，那就记这句：**两个点集里，名次相同的点，必须是同一个位置。**

> 〔停顿〕两秒，让学生消化一下，顺便看看有没有人点头。

第三个，`cameraMatrix`——**相机内参矩阵**。谁提供？**我们提供，代码里已经写好了**，就在 `main.cpp` 里那个 `camera_matrix`，你不用自己标定。它长什么样？是一个 **3 乘 3 的矩阵**，里面装着焦距 fx、fy 和主点 cx、cy 这几个数。为什么要给你？因为 solvePnP 得知道"这个镜头是怎么成像的"，才能把照片上的像素点还原回空间里。

第四个，`distCoeffs`——**畸变系数**。谁提供？同样**我们提供，代码里已经写好了**，就是 `main.cpp` 里的 `distort_coeffs`。它长什么样？是一个 **1 乘 5 的向量**，也就是 5 个数，描述这个镜头在画面边缘的弯曲程度。

这两个"我们提供"的参数，你原样传进去就行，一个字都不用改。但你要明白它们为什么重要：**它们其实就等于"当前这个镜头、当前这个分辨率"的身份证，换了镜头或者换了分辨率，这两个就得重来。**

> 〔操作〕鼠标划到后两个必填参数。

再往下两个必填参数是**输出**——注意，是"输出"，也就是函数算完，往里填结果的。第五个 `rvec` 是**旋转向量**，第六个 `tvec` 是**平移向量**。你只要提前准备好两个变量，让函数往里写就行。它俩的细节，我们下一页专门拿出来讲透，现在先认识个脸熟。

> 〔操作〕鼠标划到最后两行带默认值的参数。

后面还有两个参数，`useExtrinsicGuess` 和 `flags`，都带着默认值。今天一句话带过：**用默认值，不用管。** 前者默认是 `false`，意思是"我们不给它猜一个初始值"；后者默认是 `SOLVEPNP_ITERATIVE`，意思是"用它默认的迭代解法"。今天这两个都不用动。

为什么？因为 `solvePnP` 这个函数，它自己不知道哪个点在左、哪个在右。它只知道「你给我的第 i 个 3D 点，对应你给我的第 i 个 2D 点」。顺序错了，它照样给你一个解——但那个解是错的，而且它不报错。

### 【幻灯片 17】Task 01 · 填写 object_points　⏱ 5 分钟

> 〔操作〕翻到第 17 页，切到 IDE，打开 `src/main.cpp`，光标停到文件开头的 Task 01 注释处。

Task 01 在 `main.cpp` 的文件顶部，大概二十几行的位置。

先说一个**很多人会卡住的细节**：这一段模板，现在是**整段被双斜杠注释掉的**，你在编辑器里看到的是一片绿字。所以第一步不是填数字，是**先解注释**——把它前面的 `//` 去掉，让它变成真正生效的代码。这个提醒很重要，不然后面 solvePnP 会报「找不到 object_points 这个名字」，你还以为是别的地方错了。

> 〔操作〕指幻灯片上的模板代码块。

它现在在文件里是这样——整段都被双斜杠注释着：

```cpp
// static const std::vector<cv::Point3f> object_points {
//     {          ,           , 0 },  // 点 1
//     {          ,           , 0 },  // 点 2
//     {          ,           , 0 },  // 点 3
//     {          ,           , 0 }   // 点 4
// };
```

你要填的是每个点的前两个空——第一个是 x，第二个是 y。

这个坐标系叫**装甲板局部坐标系**：**原点在板的正中心，x 轴向右为正，y 轴向下为正。** 因为四个角点都躺在同一张平板面上，所以它们的 z 分量**全是 0**，这个 0 已经帮你填好了。

> 〔操作〕鼠标框住幻灯片上 `ARMOR_WIDTH / 2` 那一句。

代码注释里明确要求：**用「± ARMOR_WIDTH / 2」这样的写法来填，不要写死小数。** 为什么？因为装甲板的尺寸会改，你写成 0.0675 这种硬编码，尺寸一改你全得重来；写成表达式，尺寸改了它自动跟着变。宽度方向用 `ARMOR_WIDTH / 2`，高度方向用 `LIGHTBAR_LENGTH / 2`——一个是半宽，一个是半高。

现在我们一起推，我不给答案。

> 〔板书〕黑板上画一个矩形，标出中心，画上向右的 x 轴、向下的 y 轴。

> 〔停顿〕等三秒。

第 1 个点，左上角。它相对板中心，是偏左还是偏右？偏左的话，x 应该是正的还是负的？

> 〔停顿〕

它在上方。y 轴是朝下的——越往下 y 越大——那最上面这个点，y 是正的还是负的？

> 〔停顿〕

> 〔应答〕
> · 学生推出正确的符号 → 「对，这是你自己推出来的。思路就对了：先看这个点落在中心的哪一侧，再对照轴的方向。剩下三个点，照这个来。」
> · 学生把符号说反了 → 「先别急着背结论。把 x 轴、y 轴画在纸上，看这个点落在轴的哪一侧。y 轴朝下、越往下越大——那最上面这个点的 y，应该更大还是更小？」
> · 冷场 → 「我给思路不给答案：先别管正负，把绝对值填进去，四个点都是半宽和半高；正负号，就看你这个点在中心的哪一侧。剩下的你们自己推。」

好，剩下的三个点，照同样的道理自己推。我不念答案。

再提几个我见过的常见错误，你们避开：

第一，**正负号搞反**——最常见。第二，**把 0.135 当成半宽**——0.135 是灯条中心间距、是两个灯条中心的距离，半宽是它的一半，别再除第二次。第三，**忘了解注释**，就是你前面遇到的那个。第四，**顺序写错**——四个点的注释都给你标了号，别填岔行。

> 〔操作〕切到 `tasks/armor.hpp`，指一下 `Armor` 结构体里的 `center`。

还有一句提前提醒：**`Armor` 结构体里那个 `center`，不是装甲板四边形的角点。** 它是那 4 个关键点的平均值，也就是这个四边形的形心——一个算出来的虚拟点，不是四个角里的任何一个。PnP 要的是能和物理 3D 点一一对应的那四个真实端点，别拿 `center` 来凑数。

### 【幻灯片 18】点序陷阱：注释是错的　⏱ 4 分钟

> 〔操作〕翻到第 18 页，投影切回 IDE，打开 `tasks/armor.hpp`，光标停到 `points` 那一行。

**这条注释是错的。**

实测下来的真实顺序是**左上、右上、右下、左下**——自左上顺时针。注释写的那个是逆时针，正好反了。

那我怎么知道的？两种办法，现场都能做。

**第一种，三秒钟就能看出来。** 程序里那行 `tools::draw_points(img, armor.points)` 已经在画那四个点了。你在这四个点旁边按下标标上 0、1、2、3，跑一遍，肉眼一看就明白谁是左上、谁是左下。

> 〔操作〕切到运行中的程序，指一下画面上标注的四个点。

**第二种更硬，也更值得学。** 把 `object_points` 换成注释里写的那个顺序，重新编译一次——然后看 `reproj err` 这个数。顺序对的时候它是个位数，写反了它会跳到几十。

> 〔停顿〕

`reproj err` 是什么，我在 P5 会专门讲一页。这里你先记住结论：**它是唯一能一眼判死点序对错的工具。**

最后回到这条注释本身。它为什么会错？我猜是抄的时候没改——**因为 `armor.hpp` 里这条注释出现了两次**，文件头的信息块里有一次，成员那一行又有一次。错误的东西被复制了一遍，看起来就更像真的了。

> 〔板书〕注释是人写的，会过期；代码和数据不会撒谎。冲突的时候，信实测。

这句话记一下。以后你写代码、读别人的代码，都用得上。

### 【幻灯片 24】rvec 到底是什么　⏱ 2.5 分钟

> 〔操作〕翻到第 24 页。

好，现在揭晓。刚才那三个数叫 rvec，它的正式名字叫**旋转向量**，英文 rotation vector。一句话，你们记一下：

**它的方向，就是旋转轴的方向；它的模长，也就是这个向量的大小，就是绕这根轴转过的角度，单位是弧度。**

记住，是**弧度**，不是度。弧度跟度的换算大家不陌生，180 度等于 π 弧度。

好，现在回过头，兑现刚才那两个问题。

第一个，为什么只绕一个轴转，只有一个分量在变？现在明白了吧——因为**旋转向量是有方向的**，而这个方向就是你的旋转轴。你绕竖直的那根轴转，这个向量的方向就正好沿着竖直轴，它在另外两个方向上的分量自然就是零，所以只有对应那一个方向的分量在动。你刚才观察到"只有一个数在变"，这不是巧合，**这就是旋转向量的定义本身**。

> 〔停顿〕给学生两秒钟回味。

第二个，为什么转得越多数值越大、还会变号？因为**模长就是角度**。你转的角度越大，这个向量的长度就越长，那个在变的分量也就跟着涨——这正好解释了刚才你看到的现象：那个数随着手转过去一路变大。至于变号——还是绕这根竖直轴，你往左转 30 度和往右转 30 度，旋转轴的方向正好是反的，整个向量翻了个个儿，那个分量就从正变负了。

所以你看，rvec 这三个数不是随便蹦出来的，每一个数都在描述"往哪个方向转、转了多少"。

那问题来了——为什么 OpenCV 要用三个数来表示旋转，而不是用那个更常见的、3×3 的旋转矩阵？

> 〔停顿〕等一下。

**因为省。** 任意一个三维旋转，其实只有三个自由度，用三个数就够了。3×3 的矩阵有九个数字，但里面是冗余的，它背着一堆约束条件。rvec 三个数，不多不少，刚刚好。

那既然三个数就够，为什么下一页还要出现矩阵、欧拉角、四元数这些别的说法？我们来看。

### 【幻灯片 25】旋转的几种表示法，一张图看懂　⏱ 2.5 分钟

> 〔操作〕翻到第 25 页。

这一页就一张图，但信息量很大。我们把图上的三条箭头一个一个看清楚。

第一条，**旋转向量 rvec，经过 cv::Rodrigues 这个函数，得到旋转矩阵 rmat**。这个转换用的就是**罗德里格斯公式**。注意这条线是**可逆**的——你有一个 rvec，能算出 rmat；反过来，你有一个 rmat，也能用同一个函数算回 rvec。它俩一一对应，转过去、转回来，不丢信息。

> 〔板书〕黑板上写：rvec --（cv::Rodrigues）--> rmat，画成双向箭头。

第二条，**旋转矩阵 rmat，经过反三角函数，得到欧拉角**，也就是我们熟悉的 yaw、pitch、roll 这三个角。这条线的意思是：你手上有一个 3×3 的矩阵，想把它翻译成"先绕哪个轴转多少、再绕哪个轴转多少、最后绕哪个轴转多少"，用反三角函数就能解出来。

第三条，**旋转矩阵 rmat，经过一组转换公式，得到四元数**。四元数就是四个数，w、x、y、z，这个我们下一页还会碰到。

所以你看，**rvec、旋转矩阵、欧拉角、四元数，这四个东西本质上是等价的**——它们说的都是同一件事，就是"这个物体到底是怎么转的"，只是换了一身衣服。什么时候用哪一套，看场景：rvec 省地方，欧拉角给人看最直观，四元数在连续旋转和插值的时候最稳。

那我们这一讲要走哪条路呢？**是 rvec 先变成 rmat，再从 rmat 变出欧拉角这一条。** 为什么？因为等一下 P5 里的 Task 05，要的就是这个——它让你用 `cv::Rodrigues` 把 rvec 转成旋转矩阵，再用反三角函数把 yaw、pitch、roll 解出来。所以下一页，我们就把最后这一步**讲透**。

### 【幻灯片 26】从旋转矩阵提取欧拉角（INT_YXZ 约定）　⏱ 3.5 分钟

> 〔操作〕翻到第 26 页，标题是"从旋转矩阵提取欧拉角（INT_YXZ 约定）"。这一页是本讲最重要的理论页，速度放慢。

先看标题里那个缩写，**INT_YXZ**。这是这一页所有公式的前提，叫**旋转顺序**，也叫**约定**。

为什么非得先约定？因为欧拉角不是一步转到位，它是**分三步转**的：先绕一根轴转一个角，再绕第二根轴转一个角，最后绕第三根轴转一个角。Y、X、Z 就是这三根轴的先后顺序——先绕 Y、再绕 X、最后绕 Z。**顺序一换，同一个姿态算出来的三个数就完全不一样。** 所以公式表头才要标 INT_YXZ。记住：**用公式之前，先认约定。**

好，约定认完了，我们看公式。先说一个记号：我们把旋转矩阵 rmat 的第 i 行、第 j 列这个元素，记作 **m 下标 i j**。整张表就三个式子：

```cpp
// rmat 的第 i 行第 j 列元素记作 m_ij
yaw   = atan2( m13, m33 )
pitch = -asin( m23 )
roll  = atan2( m21, m22 )

// 注意：atan2 / asin 算出来是弧度，乘 57.3 (≈180/π) 换算成角度
```

我们一个一个看。

第一个，为什么用 **atan2**？atan2 叫**两参数的反正切**，是 C++ 标准库里就有的函数——`std::atan2(double, double)`，吃两个参数：分子的 y、分母的 x。它比旁边 asin 的值域宽得多——atan2 能给出负 180 度到正 180 度，一整圈都能表示；asin 只能给出负 90 到正 90 度，半圈。原课专门强调过，atan2 是两参数的反正切，这个一定要记住。

第二个，pitch 用的是 **asin**，反正弦。那它前面为什么带个负号？这也是**约定**带来的——因为我们这套公式是按 YXZ 的顺序推出来的，推到最后符号就落成了这个样子。你换一套约定，这个负号可能就没了。所以你不用去背这个负号的来路，你只要知道：**它是约定的一部分，跟着约定走。**

第三个，roll，也是 atan2，取的是 m21 和 m22。

> 〔停顿〕让学生把三个式子抄下来。

好，公式抄完了。接下来这一条，是我今天最想让你们记住的一步，也是**往届学生最容易错的地方**。

你们注意看公式里这些下标：m13、m33、m23、m21、m22。这些下标**都是从 1 开始数的**——m13，就是第 1 行、第 3 列。

但是，我们代码里的 rmat 是一个 **cv::Mat**。cv::Mat 的下标，是**从 0 开始**的。后面 Task 05 的代码注释里专门写了这一句：**cv::Mat 的下标从 0 开始，而不是 1。**

> 〔板书〕左边一列写公式下标，右边一列写代码下标，中间画对应线。

所以，公式里的 m13，在代码里要写成 `rmat.at<double>(0, 2)`——你看，第 1 行变成 0、第 3 列变成 2，**每个下标都减了一**。同理，我们把这五个都对应上：

> 〔板书〕
> m13 → rmat.at<double>(0, 2)
> m23 → rmat.at<double>(1, 2)
> m21 → rmat.at<double>(1, 0)
> m33 → rmat.at<double>(2, 2)
> m22 → rmat.at<double>(1, 1)

**就差这一个 1，数错一个，全盘皆错。** 你们等一下在 P5 写 Task 05 的时候，如果算出来的角度莫名其妙、跟实际转的方向对不上，第一件事就回来查这五个下标，看是不是忘了减一。这是我们今天反复要强调的一个点。

最后看一下幻灯片最后那行注释。它写着：atan2、asin 算出来是**弧度**，乘 57.3——也就是 180 除以 π——换算成角度。

这里我要提醒一句口径：**我们工程里的代码，是把弧度直接显示出来的，没有乘 57.3。** 所以等一下你在画面上看到的 yaw、pitch、roll，都是很小的数，零点几这种，那就是弧度。幻灯片上这句"乘 57.3"，是给你们的方法——**你想看度数，就自己乘 57.3。** 千万别把这两个口径搞混了，别以为屏幕上打出来的是度数。

### 【幻灯片 27】欧拉角的坑：万向锁　⏱ 2 分钟

> 〔操作〕翻到第 27 页。左右两栏，一栏欧拉角，一栏四元数，对比着看。

好，P4 最后一页，讲欧拉角的坑。

左边这一栏，欧拉角的好处是**直观、好理解**——"飞机抬头 30 度"，谁都听得懂。但它有两个短板。第一，**表示不唯一**——换个旋转顺序，同一个姿态算出来的三个角就完全不同，所以别人给你一组欧拉角，你不问约定就没法用。第二，就是这页标题——**万向锁，Gimbal Lock**。名字听着吓人，道理很直观：欧拉角就像**三个环套在一起**，正常时各管一个方向的转动。可当你转到某个特定角度，比如中间那个环转到了 90 度，**两个环就重合到一起了**——本来它俩管两个方向，现在只管一个方向了。**三个自由度，一下子丢了一个。**

> 〔停顿〕留两秒。

丢一个自由度意味着什么？意味着在这个姿态附近，你往那个丢了的方向怎么转，角度都表示不出来，运动就"卡住"了。这就是万向锁，点到为止，今天不推导。

右边这一栏的四元数，就是来解这个问题的：四个数 w、x、y、z，**没有奇异点**，连续旋转、插值特别稳；缺点是不直观。今天也不展开。

不过这个挺好玩的，我现场带你们玩一下。

> 〔演示〕打开浏览器，访问 quaternions.online，投到屏幕上。

看屏幕。左边一列是 Quaternion，四个输入框 W、X、Y、Z；右边一列是 Euler Angles，三个输入框 X、Y、Z，旁边一个下拉框叫 XYZ-Order，就是刚说的**旋转顺序**；中间是三维网格，红 x、绿 y、蓝 z。我先动右边欧拉角，把 X 调大——网格跟着转了；再调 Y、再调 Z，都实时跟着动。现在我把左边四元数的 W、X、Y、Z 也调一遍，让姿态跟刚才**一模一样**——看到没有？**两组完全不同的数，描述同一个姿态。** 这就是"本质等价"。

> 〔停顿〕网络不好就接一句："没关系，地址我放群里——quaternions.online，课后自己去玩十分钟。"

> 〔停顿〕把这句话钉一下。

我再说一遍，因为每年都有人在这里多改东西：**你只改 `fmt::format` 括号里的三个 `0.0`，别的一个字符都不要碰。** 格式串 `{: .2f}` 不用动，参数个数还是三个，`cv::Point` 那串照旧。

那怎么把一个数从 tvec 里取出来？关键就在幻灯片上这句提示：`tvec.at<double>(0)`。我拆开讲。

tvec 是 solvePnP 吐出来的一个 3×1 的 cv::Mat。注意，**它是 cv::Mat，不是数组，也不是 vector。** cv::Mat 是 OpenCV 里存矩阵的容器，你要从里面取一个元素，不能像数组那样中括号一括，得用 `.at<类型>(下标)` 这个函数。

- 尖括号里的 `<double>`，是告诉它：我要取的这个元素是个 double。tvec 内部存的就是 double。
- 后面圆括号里的 0，是下标，表示取第几个元素。
- 所以 `tvec.at<double>(0)` 得到的是一个 double，就是 tvec 的第一个元素。

三个下标 0、1、2，正好对应 x、y、z 三个方向——0 是 x，1 是 y，2 是 z。rvec 一模一样的写法：`rvec.at<double>(0)`、`(1)`、`(2)`，同样是 x、y、z。

所以你要做的，就是把原来的三个 0.0，换成 `tvec.at<double>(0)`、`tvec.at<double>(1)`、`tvec.at<double>(2)`；下面那行 rvec 照做一遍。

这里我必须钉死一件事，别想偏了：**Task 04 就是把数字打印到画面上，就这一件事，没有别的。** 这一页的核心，是让你亲手体会一次——**怎么从 cv::Mat 里，把一个元素抠出来。** 这个动作，紧接着的 Task 05 你还要再用一次，而且一抠就是好几个。

### 【幻灯片 30】Task 05 · rvec → rmat → 欧拉角　⏱ 4.5 分钟

第一步，**声明旋转矩阵，调用 Rodrigues。**

```cpp
cv::Mat rmat;
cv::Rodrigues(rvec, rmat);
```

`cv::Mat rmat;` 是开一个矩阵变量，用来装我们的旋转矩阵。然后 `cv::Rodrigues(rvec, rmat);`——把旋转向量 rvec 转成旋转矩阵 rmat。P4 那张流程图上第一条箭头，就是这一行代码。记住，这个函数是帮你把 rmat 原地填好的，你不用管它内部怎么算。

第二步，**套 INT_YXZ 公式，算三个角。** 公式上一段刚在 PPT 第 26 页讲过，我念一遍，你对着看：

```
yaw   = atan2( m13, m33 )
pitch = -asin( m23 )
roll  = atan2( m21, m22 )
```

关键在这儿——**公式里的 m13、m23 这些，都是"第几行、第几列"，是从 1 开始数的；可 cv::Mat 的下标是从 0 开始数的。** 所以每一个下标都要减一。这个对应关系，上一段我带着你们推过，这一页的提示里也写了 `rmat.at<double>(0, 2)`。现在我不直接给你答案，你自己对着写：m13 是第 1 行第 3 列，到代码里是几？m23 呢？m21、m33、m22 呢？

> 〔停顿〕二十秒左右，等学生把五个对应关系动笔写完。

m13 是第 1 行第 3 列，代码里就是提示里给的那个例子 `rmat.at<double>(0, 2)`——行、列都减了一。剩下的 m33、m23、m21、m22，你自己按同一个规矩写，写完对着提示里的例子检查，先别问、也别看旁边同学的。

写的时候盯住这个格式：`rmat.at<double>(行, 列)`，两个下标，中间一个逗号——这就是 cv::Mat 取二维元素的方式。它比刚才 tvec 多一个下标，因为矩阵是二维的，得分行、列。五个下标你全对上了，公式这一关就算过了。

第三步，**把这三个变量，喂给第三行 draw_text。** 还是老动作——把 yaw、pitch、roll 这三个变量，填进第三行 draw_text 的参数里，格式串不用动。

### 【幻灯片 31】重投影误差：给点序配一把尺　⏱ 3 分钟

> 〔操作〕翻到第 31 页。先别讲，等大家把 Task 05 跑起来。

好，都跑起来了吗？跑起来了，我们回来补一页——这一页是今天最实用的一页。

前面在 P3 第 18 页，我讲点序陷阱的时候说过一句话：**顺序写错，程序不报错、画面正常、数值还有值。** 当时我说「有一种更硬的办法能判死它」。现在我来兑现。

> 〔停顿〕

**这个办法叫重投影误差。** 名字听着唬人，思路特别朴素。

你想，我们已经解出了位姿——也就是知道了「这块装甲板在相机坐标系下的位置和朝向」。那反过来，我是不是可以**拿这个位姿，把那四个 3D 点重新投影回图像上，看看它们落在哪？**

如果位姿是对的，投回来的四个点，应该**正好落在检测器给出的那四个点上**——因为位姿就是从它们算出来的。

如果位姿是错的，投回来的点就会**偏到别的地方去**。

> 〔板书〕object_points --(解出的位姿)--> 投影回图像 --对比--> img_points

那怎么衡量「偏了多少」？就是量距离——投回来的点，和检测器给的原始点，中间差几个像素。四个点取个平均，就是这个**重投影误差**。

> 〔停顿〕让大家消化一下这个思路。

现在给你判读口径，记住这一句就够了：

**个位数像素，就是对的；两位数，就是错的。中间没有灰色地带。**

顺序写对的时候，这个数通常在 3 像素上下。你把 `object_points` 的第 2、4 点对调一下试试——它会直接跳到几十。

> 〔操作〕切到教师机运行中的参考版，指一下画面上的 `reproj err` 一行。

看我这台机器，画面上比你们**多一行**，写着 `reproj err`。你们自己那份没有这一行。

为什么你们没有？因为我没把它放进学生版——它是自查工具，不是任务。

那你们想用怎么办？特别简单：在 `main.cpp` 顶上加一行 `#include "tools/pnp_check.hpp"`，然后在画完欧拉角之后调一下 `tools::reprojection_error(...)`，把返回值画到画面上。**这是个 header-only 的工具，不用改 CMake，加一行 include 就能用。**

我为什么专门花三分钟讲这个？

因为今天这一课，最值钱的不是 `solvePnP` 那六个参数——那个你查文档就会了。最值钱的是**「当你手里的工具不给你报错的时候，你怎么自己造一个判据」**。点序错了没人告诉你，但你可以自己造一把尺去量。

### 【幻灯片 34】我真的对准了吗？　⏱ 2.5 分钟

> 〔操作〕翻到第 34 页，标题是"我真的对准了吗？"。

在回答刚才那个问题之前，我们先把一个概念钉死：什么叫"**相机坐标系**"。

大家回忆一下前面讲过的——相机坐标系，是跟相机**刚性连接**的一个坐标系。什么叫刚性连接？就是它跟相机是一体的：相机往左移，它跟着往左移；相机往上抬，它跟着往上抬；相机转个角度，它跟着一起转。相机和这个坐标系之间，不会发生任何相对运动。

那它的原点在哪？就在**镜头的光心**上。换句话说，今天画面上那个 tvec——装甲板中心相对相机的位置——它的参照点，就是镜头的光心。而在相机的坐标系里，x 向右、y 向下、z 指向镜头正前方。

好，现在我要抛一个思考题，这个题很关键，大家认真想一下：

**「如果相机在装的时候是斜的，而且它和枪管不在同一个位置，会发生什么？」**

> 〔停顿〕停三到五秒，扫一眼教室，等一两个同学开口。

> 〔应答〕
> · 学生答"那 solvePnP 就白算了" → "先别急着怪算法。solvePnP 只负责把像素算成相机坐标系里的位姿，这一步它没做错；出问题的是——我们默认这个位姿就能直接拿去开火。"
> · 学生答"会有偏差、打不准" → "对，方向没错。那我追问一句：这个偏差，是 solvePnP 算错了吗？还是别的什么东西我们压根没考虑？"
> · 学生答"不知道"／冷场 → 老师自己接："我给个提示——今天所有的数，都是相对谁算出来的？"

答案其实就藏在我们今天的每一行输出里：我们算的，是装甲板在**相机坐标系**下的位姿。可真正要开火的是枪管，不是相机。相机是斜着装的，枪管是正的；相机装在车顶，枪管在下面——这两个东西根本不在一条线上。那你算出来的"装甲板正对着相机"，和"装甲板正对着枪管"，能是一回事吗？不是。

所以结论请大家记一下：**光有"装甲板在相机坐标系下的位姿"还不够，你还得知道相机相对枪管、相对机器人本体的安装关系。** 这句话，就是从"我算对了"到"我打中了"之间，必须补上的那一段。

### 【幻灯片 35】完整的坐标变换链条　⏱ 3 分钟

> 〔操作〕翻到第 35 页，这是今天格局最大的一页。

好，那我们就干脆把整条链路，像一张图一样，铺在大家面前。

先从最原始的那一层说起——**像素坐标系**。就是我们图像上那一堆点：左上角是原点，横着是 u，竖着是 v，单位是像素。识别器吐给我们的那四个点，就活在这一层。它最直观，但也最"虚"——没有物理尺度，也没有方向。

往上走一步，是**相机坐标系**。这一步靠什么跨过去？就是我们今天学了一整天的 **solvePnP**。四个三维点、四个二维点，加上相机内参和畸变系数喂进去，它就还给我们一个 tvec 和一个 rvec，告诉我们装甲板在相机坐标系里在哪、朝哪。**这一环，今天打通了。**

再往上，是**机器人本体坐标系**——固定在这台车自己身上的一个坐标系，比如车体中心。为什么还要往上走？因为相机是装在车上的，相机眼里的世界，得翻译成"车自己觉得世界是什么样"，才能拿去控制云台、控制枪管。那这一层靠什么跨过去？**手眼标定**。手是云台、是枪管，眼是相机，标的就是相机相对机器人本体的那组变换。

> 〔板书〕黑板或白板上画四个方框：像素 → 相机 → 本体 → IMU，方框之间分别标上 solvePnP、手眼标定、实际测量安装。

手眼标定这东西，原课给大家看过一张图：相机装在机械臂的末端，机械臂动一动，相机跟着动，通过解一组 AX 等于 XB 的方程，把相机和本体之间的相对变换解出来。这是个进阶内容，今天不展开，但你们要知道有这么一步，也要知道它为什么难——因为相机和手之间，隔着一整个机械结构的安装关系。

再往上，最后一层，是 **IMU 坐标系**。IMU 是车上的惯性测量单元，测的是姿态、加速度、角速度。为什么要跟它对齐？因为机器人本体的控制是依赖 IMU 陀螺仪的，你需要知道 IMU 到本体坐标系之间的那个变换。而这一层，靠的是**实际测量安装**——IMU 装在车上的哪个位置、朝哪个方向，是量出来的，不是算出来的。

所以整条链，一句话串起来：**像素坐标系 → 相机坐标系 → 机器人本体坐标系 → IMU 坐标系**，分别靠 **solvePnP**、**手眼标定**、**实际测量安装** 这三步跨过去。

那这句话要划重点：**今天，我们只打通了第一环——从像素到相机。** 手眼标定，还有后面基于卡尔曼滤波的运动预测，都留给后续课程。所以你们今天算出来的位姿，它的参照原点，站在**相机**上。这句话请记住：今天的结果，只到相机坐标系。

好，坐标系全景就到这儿。我们把目光收回来，做今天的总结，把作业布置下去。

### 【幻灯片 37】P7 · 本讲回顾　⏱ 1.75 分钟

好，别急着关电脑，我把这节课对一遍答案。八条，我起个头，你们在心里接。

**第一条**，位姿等于位置加朝向——位置管"在哪"，朝向管"对着哪"，两个都在，才叫位姿。

**第二条**，PnP 就是：n 组一一对应的 3D 点和 2D 点，加上相机内参，解出旋转 R 和平移 t。

**第三条**，`cv::solvePnP` 输入四样数据——物体点、图像点、相机内参、畸变系数，输出两样——rvec 和 tvec。

**第四条**，tvec 就是装甲板坐标系的原点、也就是板中心，在相机坐标系下的位置。

**第五条，这条是今天新学的重点，务必记住**——rvec 过一遍 Rodrigues 就得到旋转矩阵 rmat，rmat 再过反三角函数就得到欧拉角，换一组公式还能转成四元数；这几个东西本质上是等价的，说的都是同一件事，这块板子是怎么转的。

**第六条，同样是今天的新重点**——欧拉角有它自己的坑，就是万向锁：到了特定姿态，它会丢掉一个自由度。四元数没有这个问题，做连续旋转、做插值都更稳健。

**第七条**，`object_points` 和 `img_points` 必须一一对应。写错了，程序不报错、画面正常、数值还有值——但位姿是全错的。

**第八条**，所以要会自己造判据：**重投影误差**。把算出来的位姿投影回图像量像素差，个位数是对的，两位数是错的。今天真正想教给你的不是背下这个工具，是那种意识——**工具不报错的时候，自己造一把尺去量。**

**第九条**，完整链条是：像素到相机靠 solvePnP，相机到机器人本体靠手眼标定，机器人本体到 IMU 靠实际测量安装——而今天，我们只打通了第一环。

顺便把这一路走过来的课也顺一遍——最早是 Ubuntu 命令行和 g++ 编译，接着 CMake，再到 OpenCV，然后是面向对象，上一讲是 Modern C++，今天轮到 PnP。一环一环搭上来，才走到今天的位姿解算。

好，八条对完了。第五条、第六条是今天新学、也最容易考，第七条、第八条是我最希望你们带走的，回去都再过一遍。有没有哪一条，你想让我再说一遍的？
